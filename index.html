WHAT THIS PROTOTYPE DOES

Flag, review, then check.

Structure the request, hold review cases for a person, and only propose a slot when the resource check passes.

An illustrative service-centre problem, not a measured customer deployment. AI suggestions are not a diagnosis or a warranty guarantee. A proposed slot is not a confirmed booking.

02 / UNDER THE HOOD

The build behind
the walkthrough.

I built a Flask API, PostgreSQL storage and n8n workflow. The public demo explains them with sample data; it does not send live requests.

For technical reviewers: implementation, evidence and limits +

Implemented: server-side review gates, atomic case creation, database row locking, request IDs, bounded model timeouts and retries, urgency-based SLA proposals, technician/parts checks and approval audit events. The repository includes a 74-test PostgreSQL suite, Docker configuration and GitHub Actions checks for tests and image builds.

Not production-complete: access still uses a shared API key, reviewer identity is supplied by the caller, skill/part matching is heuristic and proposed slots are not real calendar reservations. Durable failure replay and prevention of repeated classification work remain future improvements. Business savings have not been measured.
